# 静态站改版上线标准流程

[English](README.md) | [简体中文](README.zh-CN.md)

> 纯静态站做图片和页面改版上线的一套标准流程，从本地改动走到线上核验通过。

## 这是什么

> **脱敏说明。** 本 README 已经写成通用版本。技能文件本身可能仍带有内部域名、主机名或本机绝对路径。发布前请先跑一遍扫描（见 `opensource-preflight-audit`），把命中的内容替换掉。

这不是一个上传步骤。上传是最简单的那部分，问题也不出在那里。

这套流程要消掉的失败是：本地看着是对的，线上不对，原因还看不见 —— 缓存指纹没换、批量上传漏了一个文件、或者文件本身没问题但放错了目录。流程把核验往前挪，让这种状态不会一直悄悄挂着。

## 为什么开源

我们手上跑着静态站，改动也频繁。偶尔会出现"看起来上线了，其实没有"的情况，原因永远是那三样里的一个。

把流程写下来之后，一件反复出现的悬案变成了一张清单。它是内部的工作流知识，把具体信息换成占位符之后不含任何专有内容。

## 能做什么

- **用调试协议接管后台。** 不靠网页界面一个个点，而是程序化驱动浏览器会话，批量操作可以脚本化。
- **批量上传清单。** 该传的文件全部列举出来，漏了一个能查出来，而不是等用户报上来。
- **缓存指纹同步。** 资源引用带上版本，改过的文件才会真的重新拉取，而不是被缓存兜住。
- **线上 md5 核验。** 在服务器上算文件哈希，和本地比对，把"应该已经生效了"变成一句可核对的结论。
- **一条明确的回滚路径。** 核验不过的时候有退路。

## 环境要求

Windows · Python 3 · 站点托管后台的访问权限

## 安装

```bash
git clone https://github.com/<你的用户名>/takelemon-site-deploy.git
```

然后把整个目录放进技能目录：

| 系统 | 路径 |
|---|---|
| Windows | `C:\Users\<你>\.workbuddy\skills\takelemon-site-deploy\` |
| macOS / Linux | `~/.workbuddy/skills/takelemon-site-deploy/` |

没有构建步骤，重启对话即生效。

## 怎么用

直接说要推改动：

- "把这些图更新到线上"
- "把页面改动推上去，确认生效了"
- "查一下线上和本地是不是一致的"

它会先上传、同步指纹，然后核验哈希，把实际对得上的部分报给你。

## 注意与边界

1. **"看着是对的"不构成核验。** 缓存过的浏览器截图什么都证明不了。算哈希那一步才是算数的。
2. **文件改了，指纹就得变。** 文件变了指纹没变，缓存会照旧返回，站点看起来就像改动没发生。
3. **后台会话会过期。** 耗时长的批量操作，中途可能要重开会话。
4. **发布前留一份副本。** 回滚路径的前提是有个东西可以退回去。
